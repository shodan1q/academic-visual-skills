# 设计说明与内部测试记录

> 内部记录：只用作者自己编写的合成案例，不是平台正式案例；这里不给、也不推测任何正式分数。

## 1. 为什么是“说明为主 + 两个标准库脚本”
- 上一轮经验：重型流水线在正式环境里因依赖、路径、超时直接得 0 分；说明为主的精简 Skill 稳定可用。本包只有 SKILL.md 和两个各 ≤ 200 行的标准库脚本，不安装任何东西。
- 运行预算是 64 次请求 / 900 秒。流程按 ≤ 30 次调用设计：第 3 次调用内写 result.json 骨架，之后逐步替换为真实内容。
- 快速模型手写 SVG 最常出的错（箭头方向、端点类型、箭头穿过节点、标签溢出、图例缺项）都交给 `svgfig.py build` 统一处理和告警；科学判断（实体、关系、证据强度）仍由模型基于材料完成，并强制写进实体—关系表。

## 2. 每条规则针对的失败形态
| 失败形态（题面列举） | 对应规则 / 机制 |
|---|---|
| 名词平铺成一圈，随意连线，不分激活/抑制 | 先建实体—关系表；关系语义 → 固定 type（6 种）；脚本按 type 生成端点与线型 |
| 上下游颠倒、“被抑制”方向画反 | 规则：方向 = 因果方向，“A 被 B 抑制”= B ⊣ A；er.md 记录方向依据 |
| 跨膜受体画在膜内、区室错位 | 区室 panel 自上而下；跨膜节点中心放在膜条；跨区室用 transport |
| 图例缺失或与配色不一致 | legend 项由同一 EDGE 表生成；无图例 build 告警；清单要求一一对应 |
| 推测关系画成实线 | indirect（点线）专用于间接/推测/未检验 |
| 图中数值无来源 | 节点/边/文字都必须带 `src`，缺失 build 告警；check 告警图上找不到出处的数字 |
| 只有位图 | 交付 spec + 分层 SVG（文字为 `<text>`），check 发现无 `<text>` 或无预览即 FAIL |
| 改一个标签要整张重画 | `edit` 按 id 改源，`diff` 证明其余元素不变；新版本重新渲染 |
| 字体缺失、中文变方框 | `tools` 列出中文字体；check 对“有中文但字体栈无 CJK”FAIL |
| 导出失败没有说明 | render 依次尝试 6 种渲染器并写 export_log.jsonl；失败如实记录、status partial |
| status 写成一句话、字段缺失 | check：status 必须是一个词，contract 字段不得为空/TODO |

## 3. 内部合成测试
| 项 | 内容 |
|---|---|
| 案例 | `case04`：合成 Wnt 样通路描述（7 行，含一个“未检验”的反馈）+ 3 行 log2FC 表 + 一条改标签请求；contract 用 camelCase，status 词表为 completed/partial/failed |
| 执行方式 | 作者只按 SKILL.md 步骤执行（骨架 → tools → 写 spec → build → render → edit/diff → 记录 → check），约 8 次命令调用 |
| 结果 | build 无告警（24 个元素全部带来源）；rsvg-convert 渲染 PNG 300 dpi、PDF 矢量且 12 个字体全部嵌入；edit 后 diff 只有 1 处改动、78 个 id 保留；check PASS |
| 人工查看 PNG | 区室顺序正确、反馈环绕行不穿节点、抑制为 T 端、推测边为灰色点线、图例 9 项与图一致 |
| 注入测试 | 把 status 写成“done well”、字段留 TODO、缺字段：check 给出对应 FAIL；未渲染的 SVG：check FAIL “no real PNG/PDF preview” |

## 4. 仍做不到的
- 不自动排版：坐标由模型给出，脚本只告警。
- 文字宽度是估算值；极端长标签以渲染结果为准。
- 不验证机制在生物学上是否成立；只保证与材料一致、证据强度可见。
- 纯文本模型读不了材料里的图片，只能依据文字与表格并如实说明。
