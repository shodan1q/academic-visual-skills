# 设计说明与内部自测记录（内部材料）

> 只记录维护者在本机真实做过的事。案例是自己编写的**合成案例**，不是平台正式案例；没有做"不加载 Skill 的基础 Agent"
> 对照运行，因此不给任何增益数字，也不推测正式分数。

## 1. 设计取舍
- 本题考的是"从材料到可讲页面的组织与交付"。所以 SKILL.md 的重心放在三张可复核的中间产物上：
  **目标卡**（目标句、听众画像、时长分配、证据强度）、**取舍表**（每个图表/结论的去向和理由）、**问答准备**（追问、口径、页码）。
  评审可以直接对照这三张表检查"为什么这样讲"，而不是只看成品。
- 文件生成交给纯标准库的 `pptx_kit.py`（运行环境不一定有 python-pptx）；检查交给 `check_result.py`。两者与 06/08/09 共用同一份代码。
- 上一期经验：重型流水线在官方环境整题失败，轻量指令型稳定。因此脚本只做确定性的事，内容判断留给 Agent。

## 2. 规则 → 针对的失败模式
| 题面列出的失败 | 对应做法 |
|---|---|
| 把摘要和 Results 逐段搬成页面 | 取舍表 + 规则 1；叙事按目标调整（评审先结论、组会加下一步） |
| 页数与讲述时长脱节 | 目标卡里逐页秒数，合计 = 时长 ±10%；checker `--slides` 精确页数 |
| 图表与页内结论不对应、编号错位 | content_map 每页 locator + 原句短引；题注列表核对编号 |
| 结论强度与证据不符 | 证据强度三级 + 规则 4（弱证据不做结果页标题、措辞匹配强度） |
| 讲解备注缺失或与页面重复 | 备注 = 过渡句 + 强调点 + 追问指向；checker 查缺失和复述 |
| 导出后字体、配色、母版不合规 | 只用模板占位符；checker `--template` 逐字节比对母版/版式/主题；pdffonts 实测 |
| 被追问时没有准备 | qa_prep.md：5–8 题覆盖机制/数据/对照/局限/推广，每题有原文位置与可翻页 |

## 4. 已知局限
- 听众画像、追问清单是推断，SKILL 要求写成"假设"并列入 uncertainty。
- 时长按 ≈1 页/分钟的经验值分配，不同学科节奏不同。
- `pptx_kit.py` 约 370 行（inspect/build/figcrop），超过"每个脚本 ≤ 200 行"的内部目标；为单文件零依赖没有再拆。

## 版本 1.1：从 08（模板适配）移植的通用修正（内部记录，未做基础 Agent 对照）
在 08 的合成难例里发现、并在这里同样适用的问题：
- 模板里正文占位符前面还有小占位符（来源/注释）时，旧 kit 把正文塞进第一个 body 占位符 → 正文缩成页脚上方一行小字。现在选面积最大的占位符，每页打印 `placed` 行。
- 有旧 deck 时只拿旧 deck 文字做数字回查，旧 deck 的错数、错图号会被当成"对得上"。现在 `--paper` 单独对论文核对，并能识别"图号与题注内容不符"。
- 字号下限"母版正文 80%"在 32 pt 母版下要求 25.6 pt，与 14 pt 表格、12 pt 图注冲突且无人检查。改为字号阶梯（正文 ≥ 工作单下限或 18 pt，表格 ≥ 14，图注 14，出处 11–12）+ `min_pt` / `--min-pt`。
- 新增逐页审计表 `slide_audit.md`、骨架 `--init`、图片拉伸检查、标题溢出估算按 LibreOffice 渲染校准（两行标题不再误报）；修正 `placeholders` 键被当成占位文字的误报。

复测（2026-11-20，本机 LibreOffice 26.2，只按本包 SKILL.md 操作）：rt07：同一论文与模板，6 分钟 6 页、跨领域基金评审听众；checker `--paper` 把我在结论页随手写的 "1000 h"（论文没有）报成 WARN，改为不带数字后通过。结果：result.json 字段齐全，PDF/PNG 页数与幻灯片数一致，checker PASS（剩余 WARN：封面标题按模板 44 pt 折成 3 行，已写进 uncertainty）。

## 版本 1.2：运行稳健性（内部记录，未做基础 Agent 对照）
针对四类会让运行时 Agent 交出残缺结果的情况：
- result.json 按固定键名组装，而 contract 用了别的键名 → 骨架文字残留、checker FAIL。现在 `check_result.py --assemble` 按键名与描述的含义映射（中英文、嵌套子字段、JSON schema / 列表 / 字典三种 contract 写法都在合成用例上试过）。
- 可选文件缺失导致组装脚本崩溃 → assemble 对每个文件做存在判断，缺了就跳过。
- 为清掉无法满足的 WARN 反复重建 → SKILL 规定 WARN 只是提示，最多重建 2 轮，剩下的写进 uncertainty。
- 没有渲染器 → `pptx_kit.py render` 自动探测、两次尝试、限时，失败写 render.json；status=partial 时 checker 把渲染类问题降为 WARN。
- 复测 rt07 时强制 `SOFFICE=none`（模拟没有渲染器）：render 写出 render.json（status failed + 原因），assemble 给出 status=partial 与 run_failures，checker 把渲染类问题降为 WARN 并 PASS，没有陷入重试循环。
