# 设计说明与内部测试记录

> 内部记录：只用作者自己编写的合成案例，不是平台正式案例；不给、也不推测任何正式分数。

## 1. 为什么是“说明为主 + 两个标准库脚本”
- 上一轮经验：重型流水线在正式环境因依赖、路径、超时得 0 分；说明为主的精简 Skill 稳定。本包只有 SKILL.md 和两个各 ≤ 200 行的标准库脚本，无安装。
- 预算 64 次请求 / 900 秒：流程按 ≤ 30 次调用设计，第 3 次调用内写 result.json 骨架。
- 装置图和路线图最常见的错是“凭空补齐”：多出部件、连上材料没写的管路、箭头反向、编号错位。SKILL.md 先要求结构化清单（部件/连接/步骤/阶段），每行带来源；`svgfig.py` 负责走线、端点、图例和告警。

## 2. 规则与题面失败形态的对应
| 失败形态 | 对应规则 / 机制 |
|---|---|
| 部件名称与材料对不上 | 部件表照抄名称与数量，同类分别编号；节点必须带 `src` |
| 管路连接被凭空补齐 | “材料没写的连接不画”，列 material_gaps，图注/图上说明 |
| 材料流向箭头反向、断头箭头 | from/to 按介质流动方向；边端点按部件边界裁剪；回流用 via 绕行 |
| 步骤编号与正文错位 | 标签以正文编号开头；编号—正文对照写进图注 |
| 并行、循环、终止条件缺失 | 3a/3b 并排、回边带次数/条件、菱形判断节点 |
| 技术路线成了并列罗列 | 阶段列布局 + 依赖箭头；并列内容不加箭头 |
| 图例颜色与图形不一致 | 介质 → 颜色/线型固定，图例项由同一表生成；无图例 build 告警 |
| 只有截图、字体缺失中文变方框 | spec + 分层 SVG；render 报告字体嵌入；check 对无预览、无 `<text>`、中文无 CJK 字体 FAIL |
| 画布溢出 | build 告警标签溢出、穿部件、via 点在部件内；check 告警越界与重叠 |

|---|---|

## 4. 运行稳定性加固（lite-1.1，内部模拟）
同一合成案例（18 页合成论文 PDF + 装置/路线工单，两张图 + 一次演示编辑），用脚本模拟运行时按 SKILL.md 发出的 13 条命令，分四种环境：

| 环境 | 1.0 的表现 | 1.1 的表现 |
|---|---|---|
| 渲染器齐全（rsvg-convert） | 正常 | 13 条命令，脚本合计约 2 s，check PASS |
| 无任何渲染器 | check 对每张 SVG 报“无预览”FAIL，按“FAIL 改到 PASS”会一直重试 | 渲染失败写入 export_log，fill 写进 export_checks；check 降为 WARN，PASS（status partial） |
| LibreOffice / Chrome 卡死不退出 | 每个渲染器各等 120 s，一张图 PNG+PDF 链 480 s，被外层 `timeout 300` 杀掉、不留 export_log；子进程残留 | 第一次渲染 120 s 后两者被标记跳过，后续渲染 0 s；进程组一并结束，无残留 |
| 无 pdftotext / fitz / pypdf（Linux，Python 3.8.20） | `pdftotext -` 失败后由模型自行摸索 | `pdf` 明确报缺口；ImageMagick 出图；check PASS，13 条命令约 6 s |

另外修正：result.json 里任何以嵌套对象结尾的字段（如 `{"figure":{"png":…}}`）在 1.0 中被当成 `}}` 占位符判 FAIL，无从修起；1.1 只扫字符串值。PDF 改为落盘 + 章节/图注地图 + 命中行，不再把整篇论文（合成样例 78 KB）一次打进上下文。

## 5. 仍做不到的
- 部件只用通用形状，不提供仪器图标库；需要逼真装置图时只能做结构示意。
- 不自动排版，坐标由模型给出。
- 纯文本模型读不了材料中的装置照片，只能依据文字与清单并如实说明。
