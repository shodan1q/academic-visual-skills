# 设计说明与内部测试记录

> 内部记录：只用作者自己编写的合成案例，不是平台正式案例；不给、也不推测任何正式分数。

## 1. 为什么是“说明为主 + 两个标准库脚本”
- 上一轮经验：重型流水线在正式环境因依赖、路径、超时得 0 分；说明为主的精简 Skill 稳定。本包只有 SKILL.md 和两个各 ≤ 200 行的标准库脚本，无安装。
- 预算 64 次请求 / 900 秒：流程按 ≤ 30 次调用设计，第 3 次调用内写 result.json 骨架。
- 装置图和路线图最常见的错是“凭空补齐”：多出部件、连上材料没写的管路、箭头反向、编号错位。SKILL.md 先要求结构化清单（部件/连接/步骤/阶段），每行带来源；`svgfig.py` 负责走线、端点、图例和告警。

## 2. 规则与题面失败形态的对应
| 失败形态 | 对应规则 / 机制 |
|---|---|
| 部件名称与材料对不上 | 部件表照抄名称与数量，同类分别编号；节点必须带 `src` |
| 管路连接被凭空补齐 | “材料没写的连接不画”，列 material_gaps，图注/图上说明 |
| 材料流向箭头反向、断头箭头 | from/to 按介质流动方向；边端点按部件边界裁剪；回流用 via 绕行 |
| 步骤编号与正文错位 | 标签以正文编号开头；编号—正文对照写进图注 |
| 并行、循环、终止条件缺失 | 3a/3b 并排、回边带次数/条件、菱形判断节点 |
| 技术路线成了并列罗列 | 阶段列布局 + 依赖箭头；并列内容不加箭头 |
| 图例颜色与图形不一致 | 介质 → 颜色/线型固定，图例项由同一表生成；无图例 build 告警 |
| 只有截图、字体缺失中文变方框 | spec + 分层 SVG；render 报告字体嵌入；check 对无预览、无 `<text>`、中文无 CJK 字体 FAIL |
| 画布溢出 | build 告警标签溢出、穿部件、via 点在部件内；check 告警越界与重叠 |

## 3. 内部合成测试
| 项 | 内容 |
|---|---|
| 案例 | `case05`：合成连续流电解装置描述（7 行），含一个“部件清单里有、位置未描述”的冷阱 |
| 执行方式 | 作者只按 SKILL.md 执行：骨架 → 读材料 → 结构化清单 → 写 spec → build → render → 演示编辑（改泵标签、加粗进料线）→ diff → 记录 → check |
| 结果 | build 无告警（11 个元素都带来源）；回流线从下方直角绕回不穿部件；冷阱未画并写进 material_gaps 与图上注释；diff 2 处改动（文字 + 线宽）；check PASS，status partial |
| 人工查看 PNG | 液体蓝、气体绿、电信号橙虚线、回流灰，图例 4 项与图一致；参数（500 mL、1 M KOH、20 mL/min、-1.2 V vs RHE）全部来自材料 |
| 共用测试 | 与其他四个包共用的 export_check 在注入测试中正确报出：status 写成一句话、字段缺失/TODO、图上出现内部 id 与“待补充”、新版本未渲染 |

## 4. 仍做不到的
- 部件只用通用形状，不提供仪器图标库；需要逼真装置图时只能做结构示意。
- 不自动排版，坐标由模型给出。
- 纯文本模型读不了材料中的装置照片，只能依据文字与清单并如实说明。
