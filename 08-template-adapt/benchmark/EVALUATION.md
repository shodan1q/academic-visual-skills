# 设计说明与内部自测记录（内部材料，不含任何正式评分）

> 只记录维护者在本机真实做过的事。案例是自己编写的**合成案例**，不是平台正式案例；没有做"不加载 Skill 的基础 Agent"
> 对照运行，因此不给任何增益数字，也不推测正式分数。

## 1. 设计取舍
- 本题的判据之一是"母版、版式、占位符继承关系可查"。所以 Skill 把"真的套用"定义成可机检的事实：
  母版/版式/主题部件与目标模板**逐字节一致**、每页 rels 指向目标版式、内容在占位符里、run 上不写字体颜色。
  `check_result.py --template` 直接检查这几条，旧 deck 改名交付会被判 FAIL。
- 文件生成用纯标准库 `pptx_kit.py`（环境不一定有 python-pptx）；它只做字符串级插入，不重写模板部件。
- 迁移靠"先列、后建"：`inspect --full` 把旧 deck 每页按角色（标题/正文/散装文本/表格行/图片/备注）列出来，Agent 写逐页版式映射表，
  再一次性 build。这样每一页都有去向，避免"只修封面和前三页"。

## 2. 规则 → 针对的失败模式
| 题面列出的失败 | 对应做法 |
|---|---|
| 原文整段粘进默认模板，母版版式没有真正继承 | 占位符继承；checker 逐字节比对 + 版式来源检查 |
| 文本框溢出后把字号压到不可读 | 母版字号阶梯 + 80% 下限；溢出 WARN 先删字/拆页/换版式 |
| 图片拉伸变形，图号与引用错位 | kit 只做等比缩放；编号照抄并统一写法；数字回查 |
| 只修封面和前三页 | layout_map 必须覆盖每页；`--slides N`；页码占位符计数 |
| 导出后字体替换、图片丢失 | PDF 页数检查、渲染后文字比对、pdffonts 实测写进记录 |
| 页脚/页码/标题位置不一致 | 页脚页码只用版式占位符；标题统一在 ph:title |

## 3. 本机自测（2026-11-20，macOS，LibreOffice 26.x，poppler 26.07，无 python-pptx）
| 测试 | 结果 |
|---|---|
| 合成案例 demo-08：旧设计模板（LibreOffice 导出、无 notesMaster）上的 6 页 deck → PowerPoint 制作的 11 版式模板，维护者只按 SKILL.md 操作 | 约 14 次调用；6 页全部迁移，图片进"图片与标题"的图片占位符容器（等比），表格为三线表，6 页都有页脚与连续页码，备注全部迁移；checker PASS（14 个模板部件逐字节一致） |
| 反例：把旧 deck 原样当成品 | checker 报 FAIL：模板版式部件缺失/不同；无 PDF 预览；status=complete 时额外 FAIL |
| 共用组件（与 06/07 相同代码） | build 的 keep 模式、溢出估算、notesMaster 自动补齐等测试见 06 的记录 |

## 4. 已知局限
- 只比对 slideMasters/slideLayouts/theme；模板若靠 `presentation.xml` 的默认文本样式定字号，那部分不在逐字节比对范围内。
- 图表对象/SmartArt 迁移只能降级为图片或原生表格。
- `pptx_kit.py` 约 370 行（inspect/build/figcrop），超过"每个脚本 ≤ 200 行"的内部目标；为单文件零依赖没有再拆。
