# 设计说明与内部自测记录（内部材料）

> 只记录维护者在本机真实做过的事。案例是自己编写的**合成案例**，不是平台正式案例；没有用另一个模型跑"不加载 Skill 的基础 Agent"，
> 所以下面不给任何增益数字。左列是维护者只按旧版 SKILL.md 1.0 在同一案例上实际操作时看到的问题；这些问题不靠本 Skill 的规则也不会被发现
> （例如照搬旧 deck 的数字，用旧 deck 文本做回查时一切"都对得上"）。

## 1. 设计取舍
- "真的套用模板"定义成可机检的事实：母版/版式/主题部件与目标模板逐字节一致、每页 rels 指向目标版式、内容在占位符里、run 上不写字体颜色。
- 旧 deck 只当排版来源，**事实以论文为准**。适配任务里最容易被忽略的错误不是版式，而是把旧 deck 的错数、错图号原样迁进新模板。
- 生成用纯标准库 `pptx_kit.py`（环境不一定有 python-pptx），只做字符串级插入，不重写模板部件；每页打印 `placed` 行，内容去了哪个占位符一目了然。
- 检查用 `check_result.py`，除了字段齐全，还写一份逐页审计表 `slide_audit.md`（版式、占位符、散装框、图片比例误差、最小字号、备注、PDF 丢字），
  作为"逐页偏差记录"交付。

## 2. 合成难例 rt08（2026-11-20，macOS，LibreOffice 26.2，poppler，无 python-pptx）
输入：3 页论文 PDF（Table 1、Fig. 2 光照曲线、Fig. 3 稳定性 94%）；9 页旧 deck（16:9、全手工文本框、Arial 红标题、第 5 页图注误作 "Fig. 3"、
第 6 页误作 "96%"、第 7 页 9 条长要点、第 9 页无备注、第 5 页图拉伸 22%）；4:3 目标模板（自定义版式名 PKU-*，PKU-Content 的占位符顺序是
**先** 12 pt "Source note"(idx 13) **后** 正文 obj(idx 1)，母版标题 44 pt、正文 32 pt，两张样例页）；工作单要求 10 页、正文 ≥ 18 pt、每页填 Source note。

| 观察到的问题（旧版 1.0） | 后果 | 1.1 的处理 | 复测结果 |
|---|---|---|---|
| 正文进了版式里**第一个** body 占位符（12 pt Source note），WARN 却建议"删字/拆页" | 10 页里 7 页正文缩在页脚上方一行小字 | kit 改为选**面积最大**的 body/obj；名字含 Source/Note/Ref/来源 的占位符只收 `source_note`；每页打印 placed 行 | 正文全部进 obj idx 1（9.0×4.7 in），出处进 idx 13 |
| 规则写"原页内容一字不改地带过来"，数字回查只对旧 deck 文本 | "Fig. 3"、"96%" 原样迁入，checker 还判 PASS | SKILL 加"事实对账"步骤（corrections.md，论文优先）；checker `--paper` 查只在旧 deck 出现的数字、图号与题注内容不符 | 反例 deck 报 `s6:96` 与 `slide 5 ... reads like paper Fig. 2`；改后 PASS |
| 字号下限写成"母版正文 80%"（此模板 = 25.6 pt），与 kit 默认 12 pt 图注、14 pt 表格冲突，且没人检查 | 要么无法满足，要么被忽略 | 字号阶梯改为：正文 ≥ 工作单下限（默认 18），表格 ≥ 14，图注 14，出处 11–12；kit `min_pt` WARN，checker `--min-pt` FAIL | 14 pt 正文的反例被 FAIL |
| 只描述 adapt，没有主线/主张标题/讲稿规则；generate（只有论文 + 模板）无路径 | 页面"像 PPT"但讲不清主线 | 三种入口；页级大纲（角色/主张/证据/版式/备注/时长）；备注写过渡与追问证据 | 10 页：封面→动机→方法→Table 1→Fig. 2→Fig. 3→机理×2→局限→结论，标题均为主张句 |
| 图注用 12 pt 浮动文本框，图片版式自带的图注占位符闲置 | 继承关系弱、散装框多 | 图片版式有空余小 body 占位符时图注写进去（继承 14 pt） | Figure 页 0 个散装框 |
| 标题溢出估算过于保守（每个两行主张标题都报 WARN） | 运行时 Agent 为清 WARN 反复改标题、浪费调用 | 标题宽度系数按 LibreOffice 渲染校准，两行标题不报；三行才报 | 只剩封面（论文原题，3 行）1 条，按规则写进 uncertainty |
| checker 把 content_map 的 `placeholders` 键当成占位文字；先查文件存在再写审计表 | 自造 FAIL | 修正正则与顺序 | 无误报 |

复测（只按 SKILL.md 1.1 操作）：约 14 次工具调用（读输入 2、骨架 1、模板/论文/旧 deck/对账 3、spec+构建 2、导出 2、看 PNG 2、记录 1、checker 1）；
10 页全部在 PKU-* 版式上，13 个模板部件逐字节一致；PDF 10 页、PNG 10 张；pdffonts 实测 Calibri → Carlito 替代已记录；checker PASS。

## 3. 规则 → 针对的失败模式（任务说明里列出的）
| 失败 | 做法 |
|---|---|
| 原文整段粘进默认模板，母版版式没有真正继承 | 占位符继承；checker 逐字节比对 + 版式来源 + 散装文本框计数 |
| 文本框溢出后把字号压到不可读 | 字号阶梯 + `min_pt`/`--min-pt`；溢出先删字/拆页/换版式 |
| 图片拉伸变形，图号与正文引用错位 | kit 只等比缩放；checker 查比例误差 > 3% 与图号—题注内容一致性 |
| 只修封面和前三页 | plan.md 覆盖旧 deck 每一页的去向；`--slides N`；审计表逐页列出 |
| 导出后字体替换、图片丢失 | PDF 页数检查、渲染后丢字比对、pdffonts 实测写进 substitutions |
| 页脚/页码/标题位置不一致 | 页脚页码只用版式占位符；缺 sldNum 的页被列出 |

## 4. 已知局限
- 只比对 slideMasters/slideLayouts/theme；`presentation.xml` 的默认文本样式不在逐字节比对范围内。
- 图号核对靠题注文字重合度，题注很短（"Fig. 2. Results"）时判不出；数字核对是字符串级，单位换算后的数会被当成"论文里没有"。
- 图表对象/SmartArt 只能降级为图片或原生表格。
- `pptx_kit.py` 约 400 行、`check_result.py` 约 380 行，超过"每个脚本 ≤ 200 行"的内部目标；为单文件零依赖没有再拆。

## 版本 1.2：运行稳健性（内部记录，未做基础 Agent 对照）
针对四类会让运行时 Agent 交出残缺结果的情况：
- result.json 按固定键名组装，而 contract 用了别的键名 → 骨架文字残留、checker FAIL。现在 `check_result.py --assemble` 按键名与描述的含义映射（中英文、嵌套子字段、JSON schema / 列表 / 字典三种 contract 写法都在合成用例上试过）。
- 可选文件缺失导致组装脚本崩溃 → assemble 对每个文件做存在判断，缺了就跳过。
- 为清掉无法满足的 WARN 反复重建 → SKILL 规定 WARN 只是提示，最多重建 2 轮，剩下的写进 uncertainty。
- 没有渲染器 → `pptx_kit.py render` 自动探测、两次尝试、限时，失败写 render.json；status=partial 时 checker 把渲染类问题降为 WARN。
- 复测 rt08：build → render → facts.json → assemble → checker PASS，result.json 的 5 个 contract 键全部按含义填好。
