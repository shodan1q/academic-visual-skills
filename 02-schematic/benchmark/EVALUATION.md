# 设计理由与内部执行记录（lite-1.6）

本文件记录作者自己的合成用例和执行观察，用于说明方法和复现方式；不是任何平台的正式结果。

## 1. 要解决的失败形态
| 失败形态（无本 Skill 时常见） | 本 Skill 的对应机制 |
|---|---|
| 抑制画成激活、上下游颠倒、包含画成并列 | 关系语法表 + 带类型的边（颜色+端点）+ 嵌套分区；`step` 边与步骤序号相反时 WARN |
| 图里出现材料没有的名字、数值 | 每行规格带 `@行号`；`source_trace` 把指针解析成原文引句与页码，并核对节点名是否在所引行或全文出现 |
| 图例与数据表对不上、颜色数与类别数不一致 | 颜色只从 CSV 读，一类一色，图例由脚本生成；改色撞色自动换开；像素自检核对图例色块 |
| 推测关系画成既定事实 | 证据强度是独立维度（点线/点划线）；计划中、未实现的部件用虚线框 + 自动脚注 |
| 只有位图、改一个标签要重画 | 分层 SVG（真实文字、稳定 id、data-src）+ 行式规格；`edit` 行重建 v2，`edit_diff.json` 分开列内容改动与重排 |
| 渲染后箭头丢失、标签看不见 | 端点为普通多边形（不依赖 marker）；pixcheck 在渲染像素上核对端点、标题、标签墨迹 |
| 流程太长，做不完或漏掉交付物 | 两条命令：`start` 即写如实的 partial 结果；一次 `build` 出齐全部交付物；之后只修被点名的问题 |

## 2. 内部用例（合成材料，作者自测）
| 用例 | 材料 | 图型 | 设的陷阱 |
|---|---|---|---|
| MITO | 合成论文 PDF（96 行）+ 11 行蛋白分类表 + 工单 | 两个子图的机制/区室图 | 结果与方法剂量不一致；方法多出一个受体；未检验的磷酸酶；修改请求的新颜色与已有类别撞色 |
| NUCPLATE | 合成论文 PDF（60 行）+ 9 行步骤表 + 工单 | a 流程图（9 步 + 弃去分支）+ b 软件包结构（三层嵌套） | 固定时间前后不一致；计划中未实现的模块；工单要求 TIFF |

## 3. 执行观察
| 项 | 旧流程（lite-1.2，九步、手写坐标规格） | lite-1.6 |
|---|---|---|
| 完成一例所需的工具调用（按说明逐步执行） | 约 14–25 次（读任务 1–2、骨架 1、读材料 2–5、清单 1–2、规格与 build 2–4、渲染 1、来源表与图注 1–2、编辑与 diff 约 3、组装与自检 2–3） | 3–5 次（start 1、写规格 + build 1、可选重跑 0–2；另读 SKILL.md 1 次） |
| 需要手写的内容 | 实体关系清单、带坐标的 JSON 规格（MITO 用例约 9.5 KB）、v2 规格、来源表脚本、图注、result.json 填充脚本 | 一份行式规格（MITO 约 4 KB，NUCPLATE 约 4.5 KB），无坐标 |
| 脚本耗时（MITO，600 dpi，含 v2 与两次导出） | 多次分步命令 | build 一条命令约 17 s；NUCPLATE（300 dpi）约 12 s；无外部渲染器时内置渲染约 9 s |
| 首份完整 result.json 出现的时间 | 流程末尾 | start 后即有 partial 版；第一次 build 后为完整版 |
| 仅用 ImageMagick 栅格化 SVG | 箭头端点丢失（marker 不被渲染），方向不可读 | 端点、T 形端、圆点端全部可见 |

一个只读了 SKILL.md 的新代理在 NUCPLATE 用例上：共 3 次工具调用（读说明 1、start 1、写规格 + build 1），约 71 s，一次 build 即得到全部文件；它指出的三处问题（工单要求的 TIFF 未处理、无法表达“计划中”的虚线框、空分组）已在本版修正并复测。

另一个新代理在 MITO 用例上：共 4 次工具调用（读说明 1、start 1、写规格 + build 1、按 `source trace` 提示改一个行号后重跑 1），约 101 s。它写的节点顺序与作者不同，初版排版有 18 处连线交叉；加入“同组节点换位”后同一份规格为 0 处交叉，作者自己的规格保持 0 处，NUCPLATE 的编号流程保持书写顺序并排成蛇形。

鲁棒性自测：规格里写错分组名、重复 id、未定义节点的边、读不了的颜色表、无法解析的行、匹配不到目标的 edit —— build 均不中断，逐条点名并如实降为 partial；PATH 中没有任何外部渲染器时退到内置渲染，PNG/PDF 仍产出。四个脚本均通过 Python 3.8 语法检查（`ast.parse(feature_version=(3, 8))`）。

## 4. 已知不足
- 自动排版在节点多、跨分区连线密集时仍有交叉和偏高的版面（会 WARN 并记入 exceptions）。
- 环境缺中文字体时中文标签可能渲染成方框（pixcheck 会提示）；内置渲染用环境默认字体，字宽与估算略有出入。
- `source_trace` 的名称核对是字符串匹配，词形变化（Demultiplexing / demultiplexed）会被提示为“所引行未出现”，属于提示而非错误。
- 不支持 CMYK；EPS 依赖 pdftops 或 Ghostscript。

## 5. 版本记录
- lite-1.2：九步流程；JSON 规格手写坐标；marker 箭头。
- lite-1.3 – 1.5：自动排版、图例分栏、按宽度与最小字号自适应、多边形箭头端点、像素自检扩展。
- lite-1.6：`run.py` 两条命令 + 行式规格；来源表自动生成；虚线框；改色避免撞色；按工单转出 TIFF/EPS/JPEG；同组节点换位减少交叉、带旁支的链也蛇形排；空分组与单个排法失败不再中断。
