# 设计说明与内部测试记录

> 内部记录：只用作者自己编写的合成案例，不是平台正式案例；不给、也不推测任何正式分数。

## 1. 为什么是“说明为主 + 两个标准库脚本”
- 上一轮经验：重型流水线在正式环境因依赖、路径、超时得 0 分；说明为主的精简 Skill 稳定。本包只有 SKILL.md 和两个各 ≤ 200 行的标准库脚本，无安装步骤。
- 预算 64 次请求 / 900 秒：流程按 ≤ 30 次调用设计，第 3 次调用内写 result.json 骨架，之后逐步替换。
- 图形摘要的难点在“取舍与对应”：哪些要点上图、数值从哪来、结论说多强。这些由模型完成并强制写进面板—要点映射；坐标计算、箭头端点、柱高、图例生成交给 `svgfig.py`，避免手写 SVG 的低级错误。

## 2. 规则与题面失败形态的对应
| 失败形态 | 对应规则 / 机制 |
|---|---|
| 热闹的信息图、主线不清 | 四面板固定顺序 + 序号标题 + 面板间 step 箭头；要点数限制，次要信息进图注 |
| 实体张冠李戴、凭空加入图标 | 实体表照抄材料名称并带来源；“不用装饰图标替代材料实体” |
| 通路方向与因果相反 | 边类型语义固定（促进/抑制/转移/推测），方向 = 因果方向 |
| 图例颜色与数据编码不对应 | 图例项与填充色、边类型、数据系列一一对应；无图例 build 告警 |
| 图中数字在材料里找不到 | bars 由数据文件生成并带 src；SVG 保留 data-value，渲染前回读；check 告警来源映射中找不到的数字 |
| 结论过度（相关写成因果） | 结论强度规则 + 清单核对 |
| 只留 PNG、说不清来源 | spec + 分层 SVG + 元素来源表 + source map；无 `<text>` 或无预览即 FAIL |
| 画布溢出、字号过小、字体被替换 | 换行/缩字与溢出告警；check 查越界、重叠、小字号、中文无 CJK 字体；render 报告字体是否嵌入 |
| 改一处要整张重画 | 改 spec 重建或 `edit` 按 id 改，`diff` 记录 |

## 3. 内部合成测试
| 项 | 内容 |
|---|---|
| 案例 | `case01`：合成“生物炭降低籽粒镉”盆栽研究摘要（6 行，其中机制一句“数据未提供”）+ 2 行均值/SD 表；contract 为 `[{field, desc}]` 列表形式 |
| 执行方式 | 作者只按 SKILL.md 执行：骨架 → 读材料 → 面板映射 → python 生成 spec（bars 来自 CSV）→ build → 回读 → render → 演示编辑（改结论措辞）→ 记录 → check |
| 发现与修正 | 第一次 build 时一条边的 via 点落在目标节点内，箭头消失；据此给 svgfig 增加“via 点在节点内”告警，修正后无告警 |
| 结果 | 柱高回读 208.3/0.42 与 94.2/0.19 均 ≈ 496 px/单位；rsvg-convert 输出 300 dpi PNG 与矢量 PDF（字体全部嵌入）；diff 只含结论标签 1 处改动；check PASS，status partial（机制无数据） |
| 人工查看 PNG | 四面板顺序清楚，结果面板为视觉焦点，点线标示无数据的机制，图例 5 项与图一致 |
| 测试中的环境问题 | 一次磁盘写满导致 PNG 被截断但仍通过“文件头”检查；据此把预览有效性改为同时检查 PNG 的 IEND 与 PDF 的 %%EOF |

## 4. 仍做不到的
- 不自动排版，复杂摘要的美观度依赖模型给的坐标。
- bars 只覆盖非负数值的柱图；其他图型应由数据图表工具生成后作为独立面板说明。
- 纯文本模型读不了材料中的图片，只能依据文字与表格并如实说明。
